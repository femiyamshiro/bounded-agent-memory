# 归档与 Skill 联合审核

## 为什么用周期检测

Agent 自己执行已获授权的原生归档时，可以先对准确目标做一次静默留存审查。记忆失败不阻塞归档；审查规则不增加归档权限。

用户在客户端侧栏手动点击归档，当前没有已验证的即时语义审核 hook。已采用的替代路径是每 12 小时检测一次元数据，识别基线之后的新归档目标。空闲只运行程序，不调用模型；这不是每 60 秒扫聊天或持续录入逐轮消息。

启动和恢复建立当前基线，不自动回填历史。历史上的一次精确目标回填是独立授权批次，不能泛化为通用回填能力或重试权。

## 精确目标取证

只读取获准项目中的准确归档目标。原生列表不可避免返回的旧对话预览，在已获单独授权的本地进程中立即丢弃，不写日志、落盘或送模型。不可把这条例外推广到其他环境。

短历史可在额度内提供完整正文；长历史从完整近期轮次、有限终态头信息和较早历史游标开始。固定的临时来源工具可按需定位旧轮次、补读正文并核验全部已交付来源。

- 累计上限：32 个唯一正文 turn、32768 UTF-8 字节。
- seed、交付的历史元数据页和补读正文一起占用来源字节预算；控制状态/核验元数据及提示包装不计入。
- 额度先原子预留再交付；工具进程重启不重置额度或重复交付正文。
- 只投影用户文本和明确的 assistant `final_answer` 文本。
- 推理、commentary、工具输出、附件正文不进入证据投影；旧 phase 不明确和非文本内容保留遗漏标记。
- failed/interrupted 轮次可以作为失败上下文，不能证明成功；inProgress 拒绝，不能静默跳过。
- 目标须仍属于该项目且已归档。来源变化使本次 lease 失效；快照/hash 复核不是原子快照保证。

材料超限或缺失时标记 uncertain / needs_evidence / source_blocked，不截断条件、不扩大到全历史采集。32KiB 不是整个模型上下文或费用的硬上限。

## 一次判断，两条独立出口

**长期记忆**：只在原有资格、隐私和原文保全都成立时，通过原政策 writer 追加最多一个最小候选。写前核验全部已交付来源，包括补读。来源核验和另一个 MCP 的写入不是跨服务原子事务；已获得的原事件身份必须保留，即使后续核验失败也只能协调原事件。

**Skill**：先问是否存在具体、可复用、已有证据的方法，再查现有 Skill 覆盖。只有有必要的新方法才产生最多一份 instruction-only 草稿；格式和语义适用性分别检查。控制器落盘前再独立核对来源。格式通过不证明方法正确。

草稿保存在发现目录之外，不自动安装、调用或运行附带脚本。本地工程限制为最多 16 份、总 256KiB、单份 16KiB；私有目录 0700、文件 0600，拒绝符号链接，容量满则停止。草稿要进入正式使用，需要其适用范围内的验证与明确采用。

## 有限调度与未知结果

每日最多 10 个 worker 启动，记忆与 Skill 共用额度、单并发、单写者。按目标及终态版本去重，在异步工作前预留 attempt。已尝试版本不因提额或服务重启重跑。

worker 本地等待 300 秒、service 上限 90 分钟，不保证远端终止或不再计费。unknown 必须保留 fence，不能仅因本地进程退出清除或继续启动下一项；先核实原事件和远端状态，不盲目重发。

持久台账只保存必要 ID、hash、枚举、时间和固定计数，不保存会话正文、标题、预览、模型理由或输出日志。临时运行目录可包含原生运行日志，停止服务时清理；“临时任务”不等于 provider 不留存或系统没有元数据。

回滚可恢复 metadata-only 检测路径；保留台账、outbox、unknown 和草稿，不删除记忆、不重审旧版本。只有排队/完成的记忆或合格草稿才发最小本机通知；unknown 暂停可单次提醒，通知不证明用户已看到。
